Response Layer 0
Verify Before You Trust
L0 — Pre-Enrollment

Supply Chain + Platform Attestation

Quay scans agent images for CVEs and verifies cryptographic signatures. RHTAP provides build provenance — proof of where and how the agent was built. RHTPA analyzes software bills of materials for dependency risk. Keylime attests hardware integrity via TPM. Trustee verifies confidential computing enclaves. Hardened UBI ensures FIPS-validated base images. Bad supply chain = blocked at the door.

Quay RHTAP RHTPA Keylime Trustee Hardened UBI Certificate System Lightspeed Advisor
Result: The rogue agent's image has no cryptographic signature, no software bill of materials, and its host has no hardware attestation. It would have been blocked before enrollment.
Response Layers 1–2
Every Agent Gets a Real Identity
L1 — Credential · L2 — Token

Revocable Credentials + Scoped Delegation

IdM/FreeIPA enrolls agents into trust tier groups with host-based access rules — controlling which agents can access which services on which hosts. Red Hat SSO (Keycloak) issues individually revocable credentials and handles on-behalf-of delegation — when one agent delegates to another, scope narrows, never widens. SSO enforces scope ceilings per tier: Untrusted agents get narrow access, Sovereign agents get broad.

IdM / FreeIPA Red Hat SSO Certificate System
Result: The coding assistant gets an Untrusted-tier credential. Scope ceiling: read staging data only. Production database? Token doesn't carry that scope. Revocation: one API call.
Response Layer 3
Two-Layer Policy Enforcement
L3 — Policy

Scope Ceilings + Resource Permissions

Red Hat SSO enforces scope ceilings — the maximum any agent in a tier can request. SSO Authorization Services evaluates resource-level permissions within that ceiling. Cedar policy engine adds fine-grained, formally verifiable runtime rules. Two layers: "what can this tier access" + "what can this specific agent do." Policy is enforced at every API call, not just at login.

Red Hat SSO ACS Service Mesh AAP
Result: Even if the agent somehow obtained a valid token, the L3 policy check denies production database access for Untrusted-tier agents. Denied attempt is logged in real time.
Response Layer 4
Blast Radius = Trust Tier
L4 — Confinement

Defense in Depth — OS to Hardware

Podman rootless + SELinux/Blastwall box agents with mandatory access control labels per tier. Image Mode (bootc) makes the host OS immutable — agents can't tamper with the platform. Keylime continuously attests host integrity. Trustee verifies hardware-level secure enclaves. System Roles enforce crypto policies and SELinux config per tier. A compromised agent cannot escape.

Podman SELinux / Blastwall Image Mode (bootc) Keylime Trustee System Roles OpenShift Image Builder
Result: The rogue agent runs in a tight SELinux sandbox. It can see its own working directory. It cannot touch the network, other processes, or the filesystem. Lateral movement: impossible.
