Personas

Four primary users interact with the enforcement stack through different tools and at different layers.

SOC Analyst

Real-time monitoring, incident triage, alert investigation. First responder for agent anomalies.

Wazuh Dashboard, OCSF logs, ServiceNow

Security Architect

Policy design, trust tier definitions, enforcement stack configuration. Sets the rules agents live by.

IPA WebUI, Cedar policies, Falco rules

Platform Admin

Fleet operations, VM provisioning, service health. Keeps the infrastructure running.

Satellite, Ansible, Keylime, systemctl

CISO / Security Lead

Posture assessment, compliance reporting, risk dashboards. Needs the 10,000-foot view.

Satellite / Insights, Wazuh overview, OCSF reports

User Stories

Platform Admin
I want to see which agents are registered and their attestation status at a glance
so that I can confirm all fleet hosts are attesting before deploying workloads.
  • Query registrar DB returns agent UUID + active/inactive flag
  • Stale registrations (no quote in 24h) are flagged
Security Architect
I want to set a PCR allowlist so only known-good boot chains are trusted
so that a compromised bootloader or kernel triggers automatic revocation.
  • PCR mismatch → verifier marks agent "failed"
  • Revocation action fires within attestation polling interval
SOC Analyst
I want attestation failures to appear in Wazuh as security events
so that I can correlate TPM failures with other suspicious activity on the same host.
  • Keylime revocation triggers OCSF event with class_uid 2001
  • Event includes agent UUID, PCR bank, expected vs actual values
CISO
I want a fleet-wide attestation posture summary
so that I can report the percentage of hosts with verified boot integrity to auditors.
  • Single query returns total registered / attesting / failed counts
  • Export-friendly for compliance reports

User Stories

Security Architect
I want to define trust tiers (Blocked/Untrusted/Verified/Sovereign) with different scope ceilings
so that newly deployed agents start with minimal privileges and earn broader access.
  • 4 HBAC groups created, each with different service access
  • OBO scope ceiling enforced per group (e.g., Untrusted = read-only)
  • Promotion from Untrusted→Verified requires explicit admin action
Platform Admin
I want agent revocation to propagate to all enrolled hosts within seconds
so that a compromised agent cannot continue operating on hosts with stale SSSD caches.
  • sss_cache -E runs on all IPA clients after user-disable
  • Agent's next auth attempt fails within SSSD refresh window
SOC Analyst
I want to see the delegation chain for any active token
so that during incident triage I can trace which agent delegated credentials to which downstream agent.
  • Token introspection shows parent→child delegation path
  • Each hop includes timestamp and scope narrowing
CISO
I want a report of all agent identities and their trust tiers
so that I can audit the blast radius if any single tier is compromised.
  • ipa user-find filtered by trust-tier group returns count + principals
  • Identifies over-privileged agents (Sovereign tier with no recent attestation)

User Stories

Security Architect
I want to write Cedar policies that restrict Untrusted agents to read-only operations
so that a newly enrolled agent cannot modify production resources until promoted.
  • Cedar policy: forbid(principal in AgentGroup::"untrusted", action in [Action::"write", Action::"delete"])
  • Policy test suite validates deny for write attempts from untrusted principal
SOC Analyst
I want policy denials to generate OCSF events with the denied action and reason
so that I can detect agents probing for unauthorized capabilities.
  • Each deny logs: principal, action attempted, resource, policy that matched
  • Repeated denials from same principal trigger alert escalation
Platform Admin
I want to hot-reload policy changes without restarting the Cedar sidecar
so that emergency policy updates take effect immediately during incidents.
  • SIGHUP or API call triggers policy reload
  • New policy applies to next evaluation, not mid-request

User Stories

Platform Admin
I want to launch agents in network-isolated sandboxes with read-only filesystems
so that even a compromised agent cannot exfiltrate data or modify the host.
  • podman run --network=none --read-only enforced for Untrusted tier
  • Agent output only via designated /workspace/output volume
  • DNS resolution fails inside container
Security Architect
I want SELinux MCS categories to prevent cross-agent data access
so that agent A's workspace is invisible to agent B even if both run on the same host.
  • Each agent container gets unique MCS category (c0,c1 etc.)
  • Cross-category file access returns EACCES with AVC denial
SOC Analyst
I want SELinux AVC denials for agent processes to appear as OCSF events
so that sandbox escape attempts are visible alongside detection alerts in my SIEM.
  • ausearch AVCs for agent domains forward through rsyslog→Wazuh
  • Wazuh rule maps AVC to MITRE T1611 (Container Escape)
CISO
I want sandbox profile compliance reported per fleet host
so that I can verify all hosts enforce the correct confinement for each trust tier.
  • Satellite content view shows ODIS profile version per host
  • Drift detection flags hosts running agents without correct profile

User Stories

SOC Analyst
I want credential harvesting attempts to appear in my existing SIEM within 1 second of detection
so that I can triage agent anomalies without learning a new tool or checking a separate dashboard.
  • Falco detects→bridge classifies→syslog delivers in <1s
  • Wazuh alert includes: agent principal, MITRE technique, severity
  • Standard BSD syslog — works with Splunk/QRadar/Elastic too
SOC Analyst
I want the 4-phase revocation to happen automatically for critical threats
so that an agent exfiltrating credentials is contained before I finish reading the alert.
  • EDA matches swarm/exfil/escalation/escape rules
  • Phase 1-3 complete in <30s: IPA revoke→SSSD expire→contain
  • OCSF incident file written with full timeline
  • Phase 4 (ServiceNow ticket) fires if credentials configured
Security Architect
I want to add custom Falco rules for new agent behaviors without redeploying the full stack
so that detection coverage evolves as agent capabilities and threat models change.
  • Drop YAML into /etc/falco/rules.d/ → systemctl reload falco
  • Bridge auto-classifies new rule names if they follow naming convention
  • EDA rulebook matches on alert_type field from bridge
Platform Admin
I want a single make validate-siem command to confirm the detection pipeline is healthy
so that I can verify all 3 services (Falco, bridge, EDA) + SIEM intake before a demo or deployment.
  • Checks systemd status for falco, falco-siem-bridge, eda-agent-anomaly
  • Sends test event through pipeline and confirms Wazuh receipt
  • Reports pass/fail per component
CISO
I want OCSF-formatted incident records with MITRE ATT&CK mappings
so that incident reports use industry-standard formats and frameworks my board and auditors recognize.
  • Every incident file validates against OCSF v1.4.0 schema
  • attacks[] array includes technique_uid and tactic (TA0006 etc.)
  • Compatible with AWS Security Lake, Splunk OCSF add-on

Cross-Layer Workflows

1. New Agent Onboarding

Trigger: Developer requests AI agent deployment on fleet host
L0 Keylime attest host → L1 DARC enroll + kinit → L2 ahdapa scoped token → L3 Cedar policy bind → L4 sandbox profile assign → L5 Falco + bridge verify
L0 L1 L2 L3 L4 L5
Platform Admin
I want a single onboarding workflow that enrolls an agent across all layers
so that no layer is skipped and the agent starts with the correct trust tier from day one.
  • Onboarding playbook checks L0 attestation before issuing L1 identity
  • Trust tier determines L2 scope ceiling, L3 policy set, L4 sandbox profile
  • L5 detection rules active before agent's first task
  • Failed attestation at L0 blocks the entire chain

2. Incident Response — Detection to Containment

Trigger: Falco detects anomalous agent behavior (swarm, exfil, escalation, escape)
L5 Falco detect → Bridge classify + OCSF → EDA match rule → L1 IPA revoke + disable → L2 SSSD cache expire → L4 kill + contain → SIEM + ServiceNow
L5 L1 L2 L4
SOC Analyst
I want detection-to-containment to complete in under 30 seconds without human intervention
so that a credential-harvesting agent is stopped before it can exfiltrate to an external server.
  • Falco→bridge→EDA→IPA revoke→SSSD expire→kill: <30s total
  • OCSF incident file records full timeline with timestamps
  • SOC analyst sees alert + "contained" status in Wazuh
  • ServiceNow ticket auto-created if configured

3. Trust Tier Change

Trigger: Security architect promotes or demotes an agent's trust tier
L1 Update HBAC group → L2 Adjust scope ceiling → L3 Rebind Cedar policy → L4 Swap sandbox profile → L2 SSSD cache expire → L5 OCSF audit event
L1 L2 L3 L4 L5
Security Architect
I want tier changes to propagate atomically across all layers
so that an agent promoted to Verified immediately gets broader scope AND the matching sandbox profile, not one without the other.
  • Single playbook updates L1 group + L2 ceiling + L4 profile
  • Rollback on partial failure (e.g., L4 profile missing → revert L1+L2)
  • OCSF audit event records old tier→new tier with admin identity

4. Post-Incident Restore

Trigger: SOC analyst clears incident and approves agent re-enrollment
L0 Re-attest host → L1 Re-enable user → L2 Issue new token (demoted tier) → L4 Assign restricted profile → L5 OCSF restore event
L0 L1 L2 L4 L5
SOC Analyst
I want restored agents to start at Untrusted tier regardless of their pre-incident tier
so that a previously compromised agent must re-earn trust through demonstrated good behavior.
  • Re-enable assigns Untrusted group (not original tier)
  • Attestation must pass before identity is re-enabled
  • OCSF event links restore to original incident_id
  • Promotion back to original tier requires separate approval

5. Fleet Posture Report

Trigger: CISO requests weekly/monthly compliance posture summary
L0 Attestation coverage % → L1 Agent inventory by tier → L4 Sandbox compliance % → L5 Incident summary + MTTR → Combined posture score
L0 L1 L4 L5
CISO
I want a single posture dashboard combining attestation, identity, confinement, and detection metrics
so that I can answer "how secure is our AI agent fleet?" with data, not anecdotes.
  • Attestation: % hosts with passing Keylime quotes
  • Identity: agent count by trust tier, over-privileged flag count
  • Confinement: % hosts with correct sandbox profiles deployed
  • Detection: incidents this period, MTTR, top MITRE techniques
  • Single composite score: 0-100 with red/amber/green thresholds
